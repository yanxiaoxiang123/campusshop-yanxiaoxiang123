# 满 3 件包邮 · 需求澄清与测试列表

- 分支：`final/free-shipping`
- 日期：2026-10-20
- 需求位置：`docs/requirements.md` 2.7
- 范围：Java 版 CampusShop 的计价、购物车、下单 API 与页面

## 1. 模糊点与决定

| # | 模糊点 | 决定 | 理由 |
|---:|---|---|---|
| 1 | “满 3 件”是同一商品 3 件，还是购物车总件数？ | **购物车/订单总件数**，同一商品多件累加 | 课程题目写的是“订单满 3 件”，不是“同一商品满 3 件” |
| 2 | 运费多少钱？ | **10.00 元** | 用户确认 |
| 3 | 0 件（空购物车）是否收运费？ | **0.00 元** | 用户确认；空购物车没有可配送商品 |
| 4 | 运费在会员折扣之前还是之后？ | **之后**：小计 → 会员折扣 → 满减 → 加运费 | 用户确认；运费不是商品金额，不应打折 |
| 5 | 运费是否计入满 100/200 的门槛？ | **不计入**；满减只看商品折后金额 | 用户确认的顺序；否则会出现“为了凑满减先收运费”的矛盾 |
| 6 | 运费是否参与会员折扣？ | **不参与** | 运费固定 10.00 元，没有会员价 |
| 7 | 直接下单接口 `POST /api/orders` 是否也适用？ | **适用**；该接口的商品数量就是总件数 | 用户确认；否则直接下单可以绕过运费 |
| 8 | 运费是否作为独立字段返回？ | **是**；`CartDto`、`OrderDto` 增加 `shipping` | 用户确认；页面与测试都能看到明细 |
| 9 | 历史演示订单 1001、1002 怎么处理？ | 运费记为 **0.00 元**，总价保持原值 | 它们是功能上线前的历史订单，不追溯改价 |
| 10 | 退货后是否补收运费？ | **不做**，写入范围外 | 用户确认；本期只实现正向下单 |
| 11 | 数量为负数怎么处理？ | `ShippingPolicy` 拒绝负数（抛 `IllegalArgumentException`） | 防御性校验；正常入口已经限制 1～99 |
| 12 | 金额精度？ | 运费固定 `10.00`；合计保留 2 位小数 | 与需求 1.4 一致 |

### 2.6 BDD 场景：`shipping.feature`

- 场景大纲：1～4 件商品的运费与应付金额；
- 空购物车不收运费；
- 3 件不同商品也免运费；
- 2 件时运费不计入满减门槛；
- 金卡会员先折扣、再满减、最后加运费。

## 3. 需要同步修改的既有测试

因为“直接下单也适用”和“购物车总价含运费”是需求变更，以下期望值必须按新需求更新，不是为了让测试变绿而放宽断言：

| 测试 | 原期望 | 新期望 | 原因 |
|---|---:|---:|---|
| `OrderApiTest.postOrder_valid_createsOrder` | 90.00 | **100.00** | 2 件 → 运费 10 |
| `Stage2ApiTest.postOrder_valid_threeLayerAssertions` | 119.00 | **129.00** | 1 件 → 运费 10 |
| `OrderTest.order_twoNotebooks_showsOrderNumber` | ¥90.00 | **¥100.00** | 2 件 → 运费 10 |
| `Stage2ApiTest.postOrder_valid_secondThreeLayerAssertions` | 97.73 | 97.73（不变） | 3 件 → 免运费 |

## 4. 不在本期范围

- 退货/退款后的运费补收或退还；
- 优惠券与运费的叠加；
- 跨浏览器 E2E；
- 历史订单追溯改价。
